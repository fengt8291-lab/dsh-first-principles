# 台账格式规范（v1.1）

这份文档是 `first_principles_check` 的判定依据。校验器只认这里写的东西，不认"看起来像"的东西。

## 1. 位置与命名

```
<项目根>/.fp/ledgers/<slug>.md
```

一个任务一份台账。`slug` 用短横线连接的英文（校验器默认取最新修改的那份）。

## 2. 头部：三行固定字段

位于第一个 `##` 之前，`键: 值` 形式：

```markdown
# 任意标题
question: 这次真正要回答的问题（一句话）
mode: decision            # decision | diagnosis | exploration
scope: package.json, src/auth/**
```

- `question` / `mode` / `scope` 三者缺一 → `E001`。
- `mode` 不在三值内 → `E001`。
- `scope` 是这次考核的观察范围：每条模式都必须至少匹配到一个真实文件，否则 `E002`。**它同时是闸门的相关性依据**：打开闸门后，能指认路径的不可逆操作（`rm`）要求某份通过校验的台账 `scope` 覆盖该路径，否则会被问一句。用**逗号**分隔多条（`,` `，` `、`），单条里可以带空格（例如 `我的 模块/核心 逻辑.ts`）；支持 `**` `*` `?`。没有逗号时整串算一个模式，所以不要用空格分隔多条。
- `self_ref_deny`（可选）：覆盖"事实不许引用的位置"的默认禁区，见 §3.1。写 `self_ref_deny: -` 表示关掉禁区。

### 2.1 复查与确定性（可选，但建议都写）

```markdown
review_after: 2026-11-20    # 这一天之后必须重新看一遍
confidence: 0.7             # 0–1 小数，或 70%
kill: 上线两周 401 率没降就回滚   # 什么情况下承认判断失败
```

| 字段 | 规则 | 违反 |
| --- | --- | --- |
| `review_after` | `YYYY-MM-DD`，必须是真实存在的日期（`2026-02-30` 不算） | `E019` |
| `review_after` 已过今天 | 不拦通过，但报过期提醒 | `W007` |
| `confidence` | `0`–`1`（`0.7`）、或百分比（`70%`）；结论行内可覆盖 | `E018` |
| `kill` | 一句话，写清"什么可观测事件出现就承认失败"；不写不拦 | — |

日期按**本地日历日**比较，不涉及时区换算：账台上写哪一天，就按使用者本地的这一天算。

**结论行也可以带 `confidence`**，用来表达"这条比头部那条更没把握"：

```markdown
- C1 · depends: D1 · confidence: 0.5
```

为什么值得写这三行：没有 `review_after` 的结论在事实上宣布自己永远正确；没有 `confidence` 的结论会被读成 100% 确定；没有 `kill` 的判断最后会用"再坚持一下"顶替"该停了"。

## 3. 六个段落

段落标题用 `## `，大小写不敏感，也认中文别名（事实 / 假设 / 待查 / 推导 / 结论 / 失效条件）。

### Facts — 事实必须是可复核的原文

```markdown
- F1 · src/auth/session.ts:2 · `const ttl = 60 * 60 * 1000`
  可选一行说明
```

- 编号 `F1`、`F2`……（同一份台账内唯一）
- 引用 `路径:行` 或 `路径:起-止`，路径相对项目根目录，不能越出项目（越出 → `E015`）
- 路径支持中文、带空格（`我的 模块/x.ts:3`）和 Windows 反斜杠（`src\auth\session.ts:2`）；比对前统一成正斜杠
- 反引号里必须是**该行的原文**，校验器把两侧空白归一化后做子串比对

实测结果：`E003` 缺引用或缺原文 · `E004` 文件不存在 · `E005` 行号越界 · `E006` 引文与目标行不符 · `W002` 该原文在文件里出现多次（行号不足以定位）。

### 3.1 自引禁区（`E017`）

事实**不能**引用"结论性材料"，因为那等于用结论证明结论。默认禁区：

| 禁区 | 为什么禁 |
| --- | --- |
| `.fp/**`（台账目录） | 台账是某次推理的产物，不是世界的证据 |
| `**/DIRECTION.md`、`**/DECISIONS.md`、`**/adr/**` | 决策文档是本次决策的产物；引它就是在自证 |

另外，事实引用**本次台账自身**也一律 `E017`。

- 想引用外部材料（网页、论文、报价）？先把它摘录进 `docs/evidence/`，再引本地行——见 `docs/evidence/market-scan-2026-10-20.md` 的做法。
- 如果这条确实是**本项目自己定的规则/口径**（例如"我们承诺 30 天复测复用率"），在条目里标 `[policy]`：`E017` 降级为 `W006`，但引用仍然要能逐字核对。
- `[policy]` 不是万能挡箭牌：对世界的判断不能用它豁免。给本项目的承诺标 policy 是对的；给"市场有没有需求"标 policy 是耍赖。

### Assumptions — 假设必须能被证伪

```markdown
- A1 · basis: inference · falsify: 若客户端已存在本地强制刷新逻辑，则本假设失效
  假设内容
```

- `basis` 取值：`definition` / `inference` / `convention` / `external`（也认 定义/推断/约定/外部）。缺或非法 → `E007`
- `falsify` 必须写清"出现什么证据说明这条假设错了"，少于 4 个字 → `E008`

写不出 `falsify` 的，通常不叫假设，叫愿望——把它删掉或降级成待查。

### Open — 待查项必须有终态

```markdown
- O1 · probe: 在 src/auth/ 下找 refresh 端点 · deferred(等 auth 模块重构后再查)
```

- `probe` 写一次能跑完的动作（一条命令，或一次读文件），不要写"深入研究一下"
- 结尾三选一：`resolved(F2)`（落到某条证据）· `deferred(原因)` · `open`
- 三者都没有 → `E012`；`resolved(...)` 为空也一样

### Derivation — 推导是推理图，不是叙述

```markdown
- D1 · from F1,F2,A1
  由已确认的部分推出什么
```

- `from` 列出依据的编号，逗号分隔；引用不存在的编号 → `E009`
- 成环 → `E010`（第一性原理要求推导有向、可终止）

### Conclusion — 结论必须指回它的依据

```markdown
- C1 · depends: D1
  一句可执行的判断
```

- 缺 `depends` → `E011`；引用不存在的编号 → `E009`
- 注意：`depends` 指推导 `D*`，不是直接指事实

### Revisit — 结论的失效条件

```markdown
- R1 · A1
  当客户端出现主动刷新逻辑时重估 C1
```

- 段落缺失或为空 → `E013`
- **结论在推理图里能到达的每一条假设，都必须在这里出现**，否则 `E014`

这一条是整个设计的重心：第一性原理的产物不是"永远正确的结论"，而是"在什么条件下作废的结论"。

## 4. 警告（不阻断通过）

| 码 | 含义 |
| --- | --- |
| `W001` | 这条事实没有被任何推导或结论使用（背景噪音） |
| `W002` | 引文在文件里出现多次，行号不足以定位 |
| `W003` | 有结论但没有任何假设（通常意味着有一条隐含前提没摆上桌面） |
| `W004` | 结论只建立在假设上，没有任何事实支撑 |
| `W005` | `scope` 里的文件比台账新，结论可能已过期 |
| `W006` | 事实引用了台账目录/决策文档，但已标 `[policy]` 声明为项目自身的承诺 |
| `W007` | `review_after` 已经过今天（到期没复查） |
| `W008` | 项目里还有另一份没过期、问法不同的台账（大概率换题了却没交代） |

`strict: true` 时警告也算不通过。

## 4.1 错误码总表

| 码 | 触发条件 |
| --- | --- |
| `E001` | 头部缺 `question` / `mode` / `scope`，或 `mode` 非法 |
| `E002` | `scope` 里某条模式匹配不到任何文件 |
| `E003` | 事实缺 `路径:行` 或缺反引号原文 |
| `E004` | 引用的文件不存在、不是普通文件、是二进制，或超过大小上限（默认 2MB，可配） |
| `E005` | 行号越界 |
| `E006` | 引文与目标行不符 |
| `E007` | 假设缺 `basis` 或取值非法 |
| `E008` | 假设缺 `falsify`（少于 4 字） |
| `E009` | `from` / `depends` 引用了不存在的编号 |
| `E010` | 推导成环 |
| `E011` | 结论缺 `depends` |
| `E012` | Open 项没有终态，或 `resolved` / `deferred` 写空 |
| `E013` | 缺 Revisit 段 |
| `E014` | 结论闭包内的假设没有出现在 Revisit |
| `E015` | 引用路径越出项目根目录 |
| `E016` | 条目缺编号，或编号重复 |
| `E017` | 事实引用台账目录 / 决策文档 / 本次台账自身（自引） |
| `E018` | `confidence` 取值非法（不在 0–1，也不是百分比） |
| `E019` | `review_after` 不是合法的 `YYYY-MM-DD` |
| `E020` | 台账过大（默认 >4MB）或条目过多（默认 >5000 条） |
| `E021` | 台账解析过程内部异常（格式极端、编码异常） |

## 5. 规模与可移植性

这一节是为了让同一个插件在别人的电脑、别人的项目结构上也能跑：

| 场景 | 行为 |
| --- | --- |
| 会话开在子目录（monorepo 的 `packages/x`） | 向上逐层找：先找 `.fp/`，再找 `.git` / `package.json` / `Cargo.toml` 等标记；自己像项目就停在自己这层。目录里没有 `package.json` 也能从源码取引用 |
| 想强制指定项目根 | 配置 `rootDir` |
| Windows 路径 | 引用可以写 `src\a.ts:2`，内部统一转成 `src/a.ts` |
| CRLF / BOM | 台账与证据文件都容忍（台账 `\r\n`、证据文件开头的 BOM 会被剥掉） |
| 二进制文件 | 报 `E004`（"看起来是二进制文件"），不当证据 |
| 超大文件 | 单个证据文件默认上限 2MB（`maxFileBytes` 可配） |
| 超大台账 | 超过 4MB 或 5000 条直接 `E020`，不再慢慢解析 |
| 超多文件的项目 | `scope` 扫描默认最多 2 万个文件（`maxEntries` 可配）；扫到上限时 `E002` 的提示会说明"可能只是没扫到" |
| 行号漂了 | `/fp reanchor` 按引文原文重新定位；找不到或找到多处就只报告，不猜 |
| 台账过期 | `W007` + `/fp status` 标 ⚠ + `review_after` 可以一条命令改 |

## 6. 校验器**不**检查的事

明确划界，避免把它当成万能的：

- 不判断事实是否**相关**（它只验证"你引的这行确实存在、确实这么写"）
- 不判断推导在语义上是否成立（只判断引用闭合、不成环）
- 不判断 `falsify` 写得是否**真的可证伪**（只检查它非空）
- 不判断结论是否正确（只判断它挂在一条完整的链上）

它守的是"可围栏化的错误"：没有出处的断言、写不出证伪条件的假设、悬空的待查项、不知道自己建立在什么之上的结论。这恰好是模型最容易糊弄过去的地方。
