# 评审：`docs/RESEARCH-first-principles.md`

> 评审日期：2026-10-20。被评对象 278 行，作者是同一个工作区里的另一个会话。
> 评审方式：逐节读 + 对可核验断言做复核（外部数字、插件生态、文献归属）。
> 复核记录见 `docs/evidence/market-scan-2026-10-20.md`，本文引用它时给出 `文件:行`。

## 0. 一句话结论

**这是一份能当立项依据、但不能当验收标准的调研。** 论证结构和来源质量都在平均线以上；它对"为什么需要外部检查"讲得很清楚，但对"为什么是这种外部检查"——也就是本插件真正的设计地基——没有论证，还夹了几条可被一条命令打假的生态断言。

## 2. 硬伤（按严重程度）

### 2.1 最关键的一跳没交代

§3 用四条证据（自纠失败、过程监督、谄媚、前提移除）推出"外部检查才可信"，§0 结论 3 又推一步到"关键是外部可复核的检查"。这两步都成立。

但它从没论证第三步：**为什么外部检查必须是"逐行引用 + 反引号原文"这种形式？**

现有的四条证据只支持"要有外部反馈"，不支持"反馈的粒度必须是文件行号"。中间缺的论证是：粒度太粗（"你觉得这条靠谱吗"）会被模型用一句自我评价糊过去；粒度太细（要求形式化证明）成本爆炸。为什么"引用到行"恰好落在可用区间？这需要单独论证（我建议的论据是：它是**机器可验证的最小语义单元**——行内容可以直接字符串比对，而"这行是否支持结论"仍留给人）。

这条不是文字瑕疵。**整个插件的地基就是这个判断**，而文档把它当地基直接用了。评审应当要求补写一节，而不是"读者自行领会"。

### 2.2 生态断言有三条假的

§8.3 写"不做：运行时裁决模型（`dsh-decision-layer` 已占）、多模型会审（`dsh-decision-room` 已占）、通用 ADR 模板（`madr` 已占）"。

我用插件索引逐条查了（`docs/evidence/market-scan-2026-10-20.md:51-53`）：

- `decision-room` → **0 条**，没有这个插件。
- `decision-layer` → 0 条精确命中；唯一相关的是 `dsh-phocinae`，它的描述里出现"decision-layer"字样，但那是**本机决策层的命令行审批闸门**（安全类），不是决策推理插件。
- `madr` → 0 条精确命中，5 条模糊命中全是主题皮肤。

后果不是"引错名字"这么轻：**"这三类已被占"是决定"不做什么"的唯一依据**。如果"会审"和"ADR 模板"其实没人占，那么这两块就不是"不做"，而是"待定"。一条命令就能打假的断言，写进决策依据里，说明这份文档没有对自己的事实做过校验——而这正是它要求模型做到的事。

（顺带：这正是 `E017` 要挡的那类问题。它的原稿会把"我认为生态里没有"写成事实。）

### 2.3 `falsify` 的示范是空的

§6.2 教读者"假设必须带可观测的 falsify"，给的正面例子是"如果两周内 10 个目标用户中少于 2 人愿意第二次使用"。这句话的问题是：**它不可观测**——"愿意第二次使用"由谁判定？用什么动作算"愿意"？

这不是抠字眼。插件会放过这句话（`E008` 只检查非空、且长度 ≥ 4 字），所以**文档教的正是校验器抓不住的那种 falsify**。修法很简单：把例子换成"两周内，10 个试用用户里主动再次调用该功能的人数 < 2"这种有主语、有阈值、有采集方式的句子。

### 2.4 数字对不对没标来源

§1.2 的"$600/kWh → $80/kWh""原材料约占 2%"，§3(b) 的"78%""800,000 条"，都是二手转述，但没有一处标"这是谁在哪说的、什么时候"。对一篇要求别人逐字引用原文的文档，这是双标。§9 只列了页面链接，没有把数字和链接对上。

### 2.5 缺少最强的既有形式化：GSN 与 Toulmin

这是**内容缺口**里最大的一条。文档把 ADR 当作唯一的"已成熟品类"，于是"空位"看起来很大。但论证结构的形式化早就有成熟答案：

- **Toulmin 模型**（1958）：claim / data / warrant / backing / qualifier / rebuttal —— 今天所有论证图工具的基础。
- **GSN（Goal Structuring Notation）**：工业界（含安全关键系统认证）最成熟的"结论 + 证据 + 假设"图形化标准，其中 **assumption 是一等公民，且必须与 goal 的上下文绑定**。
- **IBIS**：issue / position / argument 的讨论结构，协作决策工具的祖型。

它们说明一件事：**"结论挂在证据与假设上"不是新想法，是四十年的工程传统**。本插件的差异点应当被表述为"把这些结构做成机器可校验的文本工件"，而不是"我们发现了空位"。不引这三家，读者会误判新颖性，评审也会直接问"你和 GSN 差在哪"。（PLAN.md 的文献综述里有这三家，两份文档的知识基线不一致，属于内部矛盾。）

### 2.6 没有失败案例

全文没有一篇"有人真的这么做了、然后失败"的案例。ADR 在不少团队被弃用的原因恰恰是**填表仪式化**——而这正是本插件最大的风险。文档 §4.3 提了一句"把模板当成果"，但没有回答：**凭什么你不会重蹈 ADR 的覆辙？** 现在最诚实的答案是"因为我们有 checker 强制事实可核对"，但这句话需要被写下来并接受反驳，而不是留给读者自己发现。

## 3. 做对的地方（不要改）

1. **§2 五个误解表**——把"第一性原理=不用类比""拆得越细越好"这些常见误解一次清掉，比长篇定义有用。
2. **§6.1 四个失效模式 ↔ 四个字段的映射**——"无记忆→question，无据→Facts，谄媚→falsify，过期→Revisit"。这是全文最漂亮的一处，因为它把认知科学结论直接变成了产品结构。插件现在的六段结构就长在这上面。
3. **§7 五条边界**——主动写"它不能做什么"，而且第 5 条（社会系统有反身性，不能当物理系统拆）是真正的诚实，很多方法论文章不敢写。
4. **§5.2 三档 + §5.3 分级表**——回答了"什么时候不该用"，这是工具类文档最常缺的一节。
5. **§8.1 的定位纠偏**——"对外主张应是『决策台账 + 检查器』，不是『让你更会思考』"。这一句直接决定了插件的对外话术，价值很高。

## 4. 如果只改三处

1. **补 §2.1 那一跳**（为什么检查粒度必须是文件行），用 Toulmin/GSN 的形式化史做支撑。这是地基。
2. **修 §2.2 的三条生态断言**，改成"未发现 / 已确认存在"两档表述，并附检索方式。
3. **把 §2.3 的 falsify 例子换成可观测的**，并同步到 README 的示例里。

其余（补 GSN 一节、补失败案例、数字标源）可以做，但不动摇结论。

## 5. 对下一步的影响

评审结论不影响已经实现的 M0–M3.5：校验器拦的是"可自动判定的错误"，这一点在文档里本来就划清了（§7）。需要改的是**叙事**——对外不要说"生态空位"，要说"把 GSN/ADR 的结构做成可校验的文本工件，并给出与它们的差异"。

这也顺带解释了 `examples/trial-length.md` 为什么重要：它是唯一一份"不是关于本插件自身"的台账，能证明这套结构用在商业决策上也不违和。
