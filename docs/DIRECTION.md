# 插件方向决策（2026-10-20）

> 依据：`docs/RESEARCH-first-principles.md` 的调研结论 + 本机插件源码实测 + npm 生态扫描。本文回答一个问题：**这个插件接下来做什么、不做什么、凭什么。**

## 1. 结论先行

**定位：不做“第一性原理教练”，做“决策的可核验台账 + 检查器”。**

- **核心（做深）**：六段台账 + 引用核对 + 依赖闭合 + 失效条件。卖点是“**每一句断言都能被机器查**”，不是“更会思考”。
- **入口（做浅）**：`/fp` + 模板 + 系统提示段，让用户在 10 分钟内产出第一份能通过的台账。
- **闸门（可选，默认关）**：只对不可逆操作 `ask`/`deny`（M4），依据 `tools/pre-execute` 钩子，技术上已在本机验证可行。
- **证据管线（补上）**：把外部来源摘录进仓库，再让台账引用本地行——否则研究型决策根本用不了。
- **不做**：运行时裁决模型（`dsh-decision-layer`）、多模型会审（`dsh-decision-room`）、通用 ADR 模板（`madr`）。这三类都不产出“可核验工件”。

一句话：**别人做“替你决定”，我们做“让你的决定留下可查的痕迹”。**

## 2. 现状盘点（M4，已在本机运行）

| 维度 | 事实 |
| --- | --- |
| 形态 | DSH Cordis 插件，零运行时依赖，`link:` 装进 `~/.dsh/profiles/desktop` |
| 能力 | 系统提示段（order 85）+ `first_principles_check` 工具 + `/fp` 命令 |
| 校验 | E001–E021、W001–W007；verdict = 无错误且（非 strict 或 无警告） |
| 复查 | `review_after` / `confidence` / `kill` 已落地；`/fp review` 一条命令改日期，`/fp status` 标过期 |
| 维护 | `/fp reanchor` 按引文重新锚定行号（行号腐坏是最高频维护成本） |
| 统计 | `.fp/runs.jsonl` 记录每次校验；`/fp stats` 输出累计纠错与错误码分布（可视化面板的数据源） |
| 可移植 | 任意目录/技术栈/Windows 路径、CRLF、BOM、二进制、超大文件与超大台账都有明确行为 |
| 测试 | `node --test tests/ledger.test.js tests/apply.test.js tests/m4.test.js` → 51 passed |
| 分发 | npm 上不存在（E404），仅本机可用；无市场目录条目 |
| UI | 无面板；文本投影是 `/fp status` / `/fp stats` |
| 闸门 | 无（`gate` 配置项未实现） |
| 语义 | 不验证事实相关性、推导语义、falsify 质量、结论正确性（`docs/LEDGER-FORMAT.md` §5 已划界） |

M0 的真实价值是**验证了“可围栏化错误”能被稳定抓住**：引用不存在/行号越界/引文不符/假设无证伪/待查无终态/依赖成环/结论悬空/假设未复查。这些恰好是 LLM 最容易糊弄的地方。

## 3. 生态扫描（决策类 DSH 插件）

| 插件 | 做什么 | 与我们的关系 |
| --- | --- | --- |
| `dsh-decision-layer` 0.6.4 | 危险调用闸门、输出自检、工具收窄、循环守卫，背后是可插拔裁决模型 | 重叠在“闸门”，但它运行时裁决，不留可核验工件 |
| `dsh-decision-room` 0.10.6 | 多模型决策室：独立评审、质询、证据与分歧、修订、人工续议 | 重叠在“决策”，但重会审、重交互，不产出机器校验记录 |
| `dsh-decision-split` 0.2.5 | 决策分屏展示 | 展示层，可后置借鉴 |
| `dsh-adr` 0.0.1 | 仅占名，未发布 | 空位仍在 |
| `madr` 4.0.0 | 通用 ADR 模板（非 DSH 插件） | 证明“决策记录”是成熟品类，但无强制校验 |
| `dsh-plugin` 市场 | 3112 条社区插件索引（2026-10-20 实测，见 docs/evidence/market-scan-2026-10-20.md） | 分发渠道 |

**空位判断**：生态里没有“事实必须回到文件行、假设必须可证伪、结论依赖可追踪”的书面台账类插件。这个空位成立，但护城河不深——真正的壁垒是**检查器的判定质量 + 与真实工作流的贴合度**，不是概念。

## 4. 用户与场景

**目标用户**：一人公司 / 2–5 人小团队 / 用 agent 干活的个人开发者。共同点：没有人反对、时间碎片化、资源固定、决策即执行。

三个高频 job：

1. **方向决策**（做什么/不做什么）：不可逆、证据散落在网页与对话里 → 需要 L2 全台账 + 证据落地。
2. **排障决策**（根因是什么）：假设多、事实少 → 需要“假设带 falsify + 待查有终态”，避免拍脑袋修。
3. **agent 长任务**：上下文压缩后前提丢失、目标漂移 → 需要 `question` 与 `Revisit` 作为锚点，闸门兜底不可逆操作。

**非目标**：需要多人协作投票的团队决策；需要合规审计的大型组织；把插件当“自动决策器”的用户。

## 5. 候选方向与取舍

| 方向 | 描述 | 成本 | 风险 | 判断 |
| --- | --- | --- | --- | --- |
| A 教学型提示词 | 系统提示教“第一性原理五步法” | 极低 | 模型本身就会，不可验证，无差异 | 只作为入口文案，不做产品 |
| **B 可核验台账** | 六段 + 检查器 + `/fp` | 中 | 写作摩擦高；可能沦为仪式 | **核心** |
| C 运行时闸门 | pre-execute 拦截高风险调用 | 中 | 与 `dsh-decision-layer` 正面重叠；误阻断会遭弃用 | 作为 B 的可选增强（M4） |
| D 决策室 UI | 多模型评审 + 面板 | 高 | 与 `dsh-decision-room` 重叠；UI 维护成本高 | 不做 |
| E 证据管线 | 抓取→摘录→本地行→台账引用 | 中 | 无直接竞品；是 B 的必要前置 | **内置能力** |

**为什么 B 而不是 C**：闸门只能拦“动作”，拦不住“错误的前提”。一个删除操作被批准，仍然可能基于错误假设；反之，台账能在动作之前暴露“你引的那行其实不支持你”。**检查工件比检查动作更靠前。**

**为什么 B 而不是 D**：多模型会审增加的是“更多意见”，不是“更多证据”。谄媚与自纠失败的证据（§3）说明：再来几个模型投票，仍然是软信号；文件行比对是硬信号。

**为什么现在补 E**：这是 dogfooding 暴露的真问题——本次调研的所有外部材料都无法直接引用（不在仓库、检查器不能比对），只能先写进 `docs/RESEARCH-first-principles.md` 再引。用户不会愿意手工做这一步。

## 6. 产品设计（v1.x → v2.0）

### 6.1 必须补的三件事

1. **证据落地（v1.1）**
   - 新工具 `first_principles_import`（或 `/fp import`）：输入 URL 或文本 + 摘录，写入 `docs/evidence/<slug>.md`，返回可引用的 `路径:行`。
   - 约束：保留 URL、抓取日期、原文；不自动改写原文；同一 URL 去重。
   - 验收：导入后生成的台账能直接 `verdict=pass`，且 `W002`（引文重复）不误报。

2. **复查字段（v1.2，已完成 = M4）**
   - 头部可选：`review_after: 2026-11-20`（`E019`/`W007`）、`confidence: 0.6`（`E018`）、`kill: <可观测条件>`。
   - `/fp status` 列出到期台账并标 ⚠；`/fp review <日期>` 直接改写；`/fp reanchor` 修漂掉的行号。
   - 同时补齐**稳性与可移植**：根目录定位、路径/编码/大小容错、`E020`/`E021` 闸门、`.fp/runs.jsonl` 运行记录。
   - 依据：决策日志（预期/概率/身心状态）与预注册（先写死证伪条件）的成熟实践。

3. **可选闸门（v1.3 / M4）**
   - `tools/pre-execute` 钩子；策略：仅当 `gate: true` 且工具属于不可逆集合（删除、发布、支付、批量写）时返回 `{kind:'ask', reason}`；读操作与可逆写不拦。
   - 默认 `gate: false`；首次开启需在 `/fp` 里显式确认。
   - 依据：贝索斯 two-way doors；避免“每步审批”的仪式化。

### 6.2 明确不做

- 不做自动“裁决模型”（不与 `dsh-decision-layer` 竞争）。
- 不做多模型会审/投票（不与 `dsh-decision-room` 竞争）。
- 不做通用 ADR 生成器（`madr` 已占；我们只在台账里兼容 ADR 字段）。
- 不做语义评分/“推理质量分”（无法可靠判定，且会制造虚假权威）。
- 不做默认开启的强阻断（会把用户逼到关闭插件）。

### 6.3 UI 的时机

先有 `/fp status` 的文本投影（台账列表、verdict、到期复查），再考虑侧栏面板。UI 的价值在“让复查发生”，不在“让写作更酷”。没有复查习惯之前做面板，是在给一个没人用的流程装修。

## 7. 路线图（调整后）

| 里程碑 | 内容 | 验收 |
| --- | --- | --- |
| M1（已完成） | 解析 + E001–E017 / W001–W006 + strict | 34 tests 通过；真实台账能复现错误码 |
| M2（已完成） | 证据核对 + 模板真实事实 + 中英别名 | 模板开箱 `verdict=pass`；E006 能抓住改一个字的引文 |
| M3（已完成） | `/fp` 命令 + 提示段 + 报告渲染 | 无参调用返回可写模板；`/fp <file>` 可校验 |
| **M3.5（已完成）** | **证据落地**：`docs/evidence/` 约定 + 自引禁区 `E017`/`W006` | 外部材料先落盘再引用；台账引用决策文档会被打回 |
| **M3.6（新增）** | **跨会话锚点**：用 `sessionProjections` 把 `question` / `C*` / 未决 `O*` 投影成会话级状态 | 新会话里能查到上一个会话的 question 与结论；目标漂移会被指出 |
| **M4（已完成）** | **复查字段 + 可移植**：`review_after`/`confidence`/`kill`（`E018`/`E019`/`W007`）、`/fp status` 过期标记、`/fp reanchor` 重锚、`/fp review` 盖日期；根目录定位、路径/编码/大小容错（`E020`）、`.fp/runs.jsonl` + `/fp stats` | 58 tests 通过（含 `tests/portability.test.js` 7 例：Python/Go/Rust/monorepo/中文空格路径/裸目录/自定义台账目录）；过期台账被标出；改文档后一条命令修复全部漂移；没有 `package.json` 的项目也能开箱生成可过检骨架 |
| **M5（已完成）** | **可选闸门**：`tools/pre-execute` 监听器，只对不可逆操作（`rm -r`/`git push --force`/`npm publish`/`gh * delete`/`docker rm`/`kubectl delete`/`drop table`/`dd` 写盘）返回 `ask`；默认关，`/fp gate on\|off` 可切，判断落 `.fp/gate.jsonl` | 66 tests 通过（闸门 8 例；面板与 inject 修复后全套 75）；关着零打扰、打开后普通命令不碰；询问日志可回看，误拦率可观察；拿不到上下文时一律放行 |
| M6 | 分发：npm 发布 + `dsh-plugin` 市场条目 + 双语 README + 3 个示例台账 | `npm view dsh-first-principles` 有版本；市场可搜到 |
| **M7 v1（已完成，2026-10-20）** | **纠错面板（Web UI）**：`conversation.composer.dock` 状态栏 + 详情面板，一键开关闸门、按会话展示每轮修掉的错误码、台账过期与闸门判定；数据读 `.fp/runs.jsonl` / `.fp/gate.jsonl`，数据面 `/x-first-principles/state`（GET）/`/gate`（POST） | 75 tests（面板 7 例 + 装配 8 例）；面板数字与 `/fp stats` 同源（同一 `summarizeRuns`）；`runs.jsonl` 起 M4、`gate.jsonl` 起 M5，历史不缺 |

**关于 M7 的时机**：用户 2026-10-20 明确提出“想让大家看到这个插件帮自己纠了多少错”，随后在 M5 收尾时改口“发布之前还是做一个前端”。所以 M4 先把**数据**记全（`runs.jsonl` 一行一次校验）、M5 记闸门判定，M7 v1 只做展示层与闸门开关，不改判定逻辑。面板第一屏回答三件事：闸门开没开、这一轮修掉了哪几个错误码、哪份台账该复查了。

## 8. 分发与增长

1. **先发布再推广**：`npm publish`（当前 E404 是最大漏斗漏洞），版本从 0.1.0 起，README 顶部放“60 秒上手”。
2. **进市场**：提交 `dsh-plugin` 目录（3112 条插件的入口），标题写“可核验决策台账”，关键词覆盖 first principles / decision / ADR / premortem。
3. **示例即文档**：三个真实台账（方向决策、排障、agent 任务），每个都能被检查器跑通；这比功能列表有说服力。
4. **对比页**：明确写“我们不做运行时裁决/多模型会审”，把选择权交给用户，减少误解。
5. **不追热点**：不把“第一性原理”当营销词堆砌；对外主张始终是“可核验”。

## 9. 风险与 kill criteria

| 风险 | 信号 | 应对 |
| --- | --- | --- |
| 写作摩擦导致弃用 | 生成台账后 7 天内无第二次使用 | 降级为“3 事实 + 2 假设”轻模板；提示段改为按需触发 |
| 沦为仪式 | 台账全过但结论明显错误（语义空洞） | 增加“反例/红队”提示；明确不承诺语义正确；用示例展示“过检但错”的案例 |
| 闸门误伤 | 用户第一次开启后 24h 内关闭 | 缩小不可逆集合；改为“只提示不阻断”的观察模式 |
| 生态重叠 | `dsh-decision-layer` 增加台账导出 | 差异化转向“证据管线 + 复查”，不与其争闸门 |
| 无人分发 | 发布 30 天安装 < 50 | 停更或并入更大工作流插件，不无限投入 |

**Kill criteria（写死）**：发布后 30 天，若“生成过台账的用户中第二次使用率 < 10%”，则停止扩功能，只保留 `/fp` 与模板，把精力转到证据管线或并入其他插件。

## 10. 待确认的决策点（需要用户拍板）

1. **是否现在发布 npm**（需要 npm 账号登录；这是唯一需要用户操作的配置）。
2. **M4/M5 顺序**：先复查字段还是先闸门？（建议先复查——闸门依赖“什么算不可逆”的稳定定义。）
3. **是否要侧栏 UI**：已排进 M7。M4 起 `runs.jsonl` 已在积累数据，面板随时可接；建议先发布 M5/M6，用 `/fp stats` 的真实数字再决定面板形态。
4. **品牌**：保留 `first-principles` 名称，还是加副标题“可核验决策台账”？（建议保留名称 + 副标题，降低认知成本。）
